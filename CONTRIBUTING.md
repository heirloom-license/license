# Contributing

Thanks for helping make the Heirloom License a trustworthy standard.

## Ways to help

- **Adopt it** and add your app to `ADOPTERS.md` — adoption is the most useful
  contribution a license standard can get.
- **Red-line the text.** Lawyers and developers: poke holes in `LICENSE.md`. Open
  an issue describing the clause, the problem, and a suggested fix.
- **Improve the tooling.** The reference dead-man's switch in `reference/` and the
  site in `site/` welcome improvements.

## Ground rules

- Changes to the operative license text ship only as a **new version** (see
  `GOVERNANCE.md`). Don't edit a published version's wording.
- Editorial, docs, and tooling changes can target `main` via PR.
- Be specific. "This clause is ambiguous" is less useful than "Section 4(b)'s
  90-day window conflicts with X because Y."

## Legal review

Open items are tracked as issues labeled `legal-review`. If you have relevant
expertise, those are the highest-leverage place to contribute.
